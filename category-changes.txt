PR title
Remember receipt item categories and report spending trends

PR description
--------------
## What

Assign one spending category to each receipt line during the existing LLM
extraction. A user's confirmed exact mapping for the same merchant and receipt
text overrides future model suggestions. Choosing or explicitly remembering a
category saves that mapping; ordinary saves, verification, and automatic analysis
do not teach new mappings. Original descriptions survive renaming, and stale
history suggestions cannot override explicit editor choices.

Add English/German category controls and monthly spending totals and percentage
shares, with period, category, currency, and collection selection. Unknown items
remain in the spending denominator. Deposits are separate; receipt-wide amounts
not allocated to lines remain visible in reconciliation. These are spending trends,
not inflation estimates, and require no package-size verification.

Migration 0008 adds category/provenance/original-description fields and private
alias mappings. Existing line items retain their data and start as unknown, except
explicit deposit tags. Legacy optional tags remain available in the editor.
A separate benchmark category-accuracy component evaluates labelled items without
changing the existing overall score.

## Why

Recurring purchases should keep the user's categories, while unfamiliar items
still get a model suggestion. A small fixed vocabulary and confirmed history
provide useful spending reports without GPC, embeddings, fuzzy overrides, or an
additional inference pass.

Operational notes
-----------------
The Docker entrypoint applies migration 0008 on restart. Normal items on existing
receipts are not automatically reclassified. History matching is exact after
case folding and whitespace normalization, scoped to receipt owner and merchant.
Changing a mapping affects future receipts, not previously stored categories.
Selecting Unknown with explicit memory removes the matching remembered mapping.

Checks use deterministic LLM fixtures; extraction/category accuracy on real
receipts has not been measured. No image data was sent to a cloud model.

On this SSHFS setup, Python checks used a local test virtualenv via
UV_PROJECT_ENVIRONMENT=/tmp/vision-bill-categories-venv. Docker E2E fixtures were
copied locally because the Docker daemon cannot traverse the SSHFS mount.
